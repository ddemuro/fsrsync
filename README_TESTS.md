## What If Tests Fail?

If tests fail:

1. **Read the error message** - it will tell you what's wrong
2. **Run that specific test** to debug:
   ```bash
   pytest test/test_filesystem_monitor.py::TestFile::test_file_creation -vv
   ```
3. **Check the logs** - tests show detailed output
4. **Fix the issue** and re-run

## Why Docker?

Tests run in Docker because:
- ✅ Consistent environment (same every time)
- ✅ Includes SSH server and rsync
- ✅ Tests actual file synchronization
- ✅ Doesn't affect your local system
- ✅ Works the same on any machine

## Prerequisites

- Docker installed and running
- 4GB+ RAM allocated to Docker
- 2+ CPU cores (recommended)

That's all you need!

## Common Issues

**Tests won't run locally?**
→ That's expected! Use Docker: `./sandbox.sh test-unit`

**Docker build fails?**
→ Clean cache: `docker builder prune -a`

**Tests timeout?**
→ Increase Docker resources to 4GB RAM
